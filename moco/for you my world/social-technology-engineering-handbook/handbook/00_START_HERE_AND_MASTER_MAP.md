The `handbook/` directory contains **65 Markdown files**: all numbered chapter files plus the master map, supporting references, AI-assistance note and handbook-local README. The repository root adds its own README, question index, license and publishing/community guidance. A root SHA-256 manifest covers the release files.

## How to study

1. Start with this master map and `handbook/README.md`; the repository landing page is the root `README.md`.
2. Read Parts 01–05 for history and computing foundations.
3. Read Parts 06–10 for application and production engineering.
4. Read Parts 11–13 for security, data/AI and distributed systems.
5. Read Parts 14–17 for product, global regulation, trust/safety and company operations.
6. Finish with Part 18, which connects those topics into a reference implementation and launch plan.
7. Use `GAP_FILL_SUPPLEMENT_00_10.md`, `TECHNICAL_GLOSSARY_AND_STUDY_GUIDE.md`, `QUALITY_AUDIT_AND_CROSS_PART_GAP_REGISTER.md` and `VERSION_STATUS_AND_SOURCE_REGISTER_2026-11-13.md` as companion references.

For every technology, ask: what problem existed, how the idea evolved, how it works internally, why teams use it, where it fails, what alternatives exist, what security/privacy risks it introduces and how to test it. Build labs only on systems you own or are authorised to use. Treat architecture examples as learning patterns, not universal prescriptions.

## Accuracy, safety and use notes

- Versions and vendor features change. The dated source register is a snapshot, not a permanent guarantee. Re-check official release notes and supported versions before implementation.
- Laws vary by country, state/province, service type, audience, scale and business model. Country chapters are engineering orientation, not legal advice. Obtain local counsel before launch.
- Distinguish enactment, publication of rules, commencement, applicability thresholds and enforcement. A law can be passed before all duties take effect.
- Data residency is not solved simply by choosing one cloud region. Check backups, logs, support access, subprocessors, transfers and contracts.
- Never test against a third-party system without explicit authorisation.
- Code and architecture samples require review, tests and adaptation before production.
