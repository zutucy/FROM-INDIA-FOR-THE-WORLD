# Contributing: corrections, questions and learning feedback

Thank you for helping make this educational resource more accurate and useful.

## Before opening an issue

1. Search existing issues to avoid duplicates.
2. Identify the exact chapter filename and heading.
3. Explain what is unclear or incorrect.
4. For factual or version-related claims, include an authoritative source link and the date you checked it.
5. Separate a confirmed error from a suggestion or personal preference.
6. Never post passwords, tokens, personal data, private messages or confidential information.

## What feedback is welcome?

- Factual corrections supported by reliable sources.
- Broken links or formatting problems.
- Missing prerequisites or unclear explanations.
- Safer lab alternatives and accessibility concerns.
- Suggestions for new questions in `QUESTION.md`.
- Reports that a package version, law or provider feature has changed.

## Pull requests and the current license

The handbook is currently shared under CC BY-NC-ND 4.0. That license does not authorize public distribution of adapted versions. For that reason, please **open an issue with a proposed correction rather than publishing a modified copy or submitting a content-changing pull request**. The project maintainer may review the suggestion and make the edit in the canonical repository.

Opening an issue does not transfer ownership of your contribution. Do not submit content you do not own or have permission to share. If a future release changes to a contribution-friendly license and formal contribution terms, this file will be updated first.

## Tone

Be specific, respectful and curious. Explain the technical reason, not just that something is “wrong”.
